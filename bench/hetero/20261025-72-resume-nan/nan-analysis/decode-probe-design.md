## Actual short-read path

Serve defaults short_read=64 (`generate.cpp:643`). The request's windows_ok test (`:10280-10286`) selects verify windows for an eligible 32-token text prompt. read_windows (`:10409-10427`) invokes Verifier::run with teacher-forced prompt tokens and disables head sampling only; those picks are discarded. Target generation uses the same Verifier::run at `:11633`. Thus the narrowest shared instrumentation point is Verifier::record_window, rather than assuming core/layer.cpp or batched Prefill::run handled these tokens. Pipelined prompt, batch slot, and pipelined decode have additional paths; confirm the selected mode from the concrete launch controls.

## Existing flags and their limits

- `STRATA_DUMP_FIRST_LOGITS=<exclusive-prefix>`: `generate.cpp:11637-11649` reads the first target-generation window's row0 logits after Verifier::run and saves `<prefix>.<counter>`. It works even when the wrong output is finite. It does not capture earlier teacher-forced prompt heads or every later decode row. This is the smallest existing full-head evidence action after the planned unchanged-driver upstream comparison, if another diagnostic run becomes justified.
- `STRATA_DBG_NAN=1`: `verify.cpp:2174-2189` checks complete head rows after the existing run stream synchronization; reports only the first nonfinite head per process. It does not locate the producing layer. Merely setting this environment variable, including value 0, enables it because the code checks presence. In batched prefill it additionally performs expensive per-MoE synchronization/readbacks (`prefill.cpp:3973-4000`) and prompt-end residual/state reads (`:4163-4180`). Its GEMM counter (`gemm.cu:803-811`) is HIP-only, so it supplies no CUDA GEMM-level scan.
- `STRATA_DIAG_ZERO_LOGITS=1`: `verify.cpp:2194-2228` reads the head only after sampled token ID0, for at most 16 such windows per process. A missing diagnostic line does not prove finite logits. Check concrete execution path, inherited variable, sampled ID, and bounded-window counter. The batch run_slot_rows / asynchronous pl_finish paths do not have this block.
- `STRATA_LOGPOS=<exclusive-path>`: the teacher-forced short-read loop (`generate.cpp:10431-10442`) reads full heads through window_logprobs. It can reveal abnormal prompt likelihoods but is not a typed finite census or a first-layer detector. On a pipelined prompt it also selects the serial loop; do not call that an unchanged path.
- CLI check-logits / dump-logits checks at `generate.cpp:12365-12379` belong to the separate ordinary generate per-token loop. The source notes at `:12809-12813` that a native pack uses verifier windows rather than that per-token dump path. Do not assume the CLI flag covers this served native request.

Any added scan or readback can perturb scheduling; disappearance of symptoms is not a repair result.

## Minimal typed coarse probe for a new isolated diagnostic revision

Reuse the bit-classification kernels and Record concept from prefill/finite_probe.cu, with a verifier-owned persistent record. Do not instantiate the current Probe as a local in record_window: record_window is called during CUDA graph capture (`verify.cpp:1752-1759`, plus batch capture at :2460-2472). Its init allocates and logs; its destructor synchronizes. Those operations do not belong inside capture.

1. Allocate one device record and pinned host receipt per Verifier/device at init, outside capture, only under an exact opt-in flag and compile guard. Disabled mode must enqueue no kernel, transfer, allocation, or synchronization.
2. At the start of each captured window, enqueue device record reset on the captured compute stream. Reset ordinal/counts to zero and index to all ones. Captured checkpoint ordinals can be fixed because each replay resets the record. Do not reuse a record across concurrently replayed windows or parity verifiers. Destroy graphs before freeing record storage.
3. Store layer, half, stage, local row and dtype in the captured checkpoint. Do NOT encode the current runtime pos0/run ID as a captured by-value constant. Attach actual host last_pos0_, T, request/window counter, device and source/binary identity when reporting after that replay's existing completion boundary.
4. First coarse checkpoints: initial R_ after embedding/restore/broadcast (`verify.cpp:836-855`); HC mixed after attention read `gr_read_group(0)` (`:1004-1010`); attention bo_ immediately after its GDN/QSA producer and before `gr_read_group(1)` overwrites/reuses storage (`:1100`, `:1327-1334`); HC mixed after half1 read (`:1334`); MoE combined bo_ after all combine branches and remote combine (`:1558-1572`) before residual/control-vector update or pre(l+1); final head_mixed_ after its mix branches (`:1667`) and head_logits_ after native/fallback projection (`:1675-1682`) before argmax/sampler.
5. R_ can have a pending fused residual write. A scan before the next fused producer is not a scan of the logically updated residual. Label materialized R separately and scan the mixed/output bo boundaries that actually exist; do not disable fused math just to create a diagnostic boundary. Cover PLE's write separately if a first-bad mixed points back to layer1.
6. Append a small record D2H copy at graph tail on the same compute stream. Consume it after the existing `run()` synchronization (`verify.cpp:2115-2118`), not by adding per-layer host waits. For batch/asynchronous completion, attach the same bounded read/report to their own existing completion path rather than assuming run() is called.
7. Main-stream scans must respect the shared-expert side stream. Scan shared_ only after the already-existing ev_join_ wait (`verify.cpp:1554`), and before next layer reuse. Do not let two independently ordered streams compete for one 'earliest' record. A later fine probe can use per-stream records and explicit ordering metadata if needed.

At this phase all coarse tensors are FP32. Keep the f16/bf16 typed scan implementation available for later producer-specific images, but never scan packed Q8 bytes as float. A finite coarse result also needs bounded min/max/argmax census of the head to distinguish finite repetitive output from all-NaN output.

## Subsequent fine probe, only after first coarse evidence

If HC mixed is finite but MoE output first fails, scan logits_/route weights; shared gate/up/activation and shared output after producer/join; actual unweighted parts_ after CPU/GPU join before combine; and consumed quantization scales with their exact layout. If attention first fails, inspect GDN/QSA output and persistent recurrent/KV inputs, retaining actual token position and layer. Keep graph math, sampling, cache tier, resident shortcuts and driver unchanged for a paired comparison. The current source does not establish a driver cause, weight corruption, or a successful fix.
