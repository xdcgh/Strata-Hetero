Source-only audit, 2026-10-25. Compared pinned base `61b3fb5dd3f1e8ec09cf7e4e05208bc6d3c46406` with fetched upstream `7dd5cf18e68c639a8773e096c5c79f971ea2a9f5` (product release v0.2.4.2). ## RAM experts and file tier

**Existing base functionality must not be reimplemented.** Base `src/program/generate.cpp:2077` already parses `--resident-budget-gib`; base `include/strata/kernels/ngram.hpp:149` has PLE RAM locking; base `generate.cpp:1811-1812` already has `--kv-resident` and `--kv-grow`. Current `FileExpertSource` remains the integration point, not a new parallel weight store.

Meaningful additions since base:

- `d7298883` adds routing-driven resident RAM replacement (`STRATA_RAM_ADAPT=n`). `src/program/generate.cpp:14954` selects unused experts of the same layer for replacement; it preserves weights/routing and caps RAM size. This changes the old description that the RAM copy is chosen only at startup.
- `c85cc6dd` adds `STRATA_RAM_ADAPT2`: `FileExpertSource::ram_stage`, `ram_install`, `ram_worker` (`include/strata/core/expert_source.hpp:823`, `:1111`), with `generate.cpp:14968` installing landed reads at window boundaries and scoring promotions by expected stalls saved per byte. Prompt routing seeds the policy with limited weight (`generate.cpp:10976`). This already implements part of a cost-aware warm expert tier.
- These promotions are guarded: the current branch at `generate.cpp:14965` requires no in-flight adaptive round, ready resident complement, one GPU, no peer/remote optimization and no batch. Do not describe it as a general multi-resource scheduler. `docs/DETAILS.md:171` also records exclusions around exchange rotation/helper GPUs.
- `f2e142f4` makes an explicit RAM budget retain the prefill loan region when it fits. Current `detail::choose_resident_keep_from`, `clamp_resident_budget` and `FileExpertSource::pin_cache_complement` logic (`expert_source.hpp:97`, `:150`; `expert_source.cpp:3527`, `:3636`, `:3669`) are the authoritative allocation rules. Requested budget is an upper bound, and prompt buffers need room too.
- `1aa0abf6` adds arena copy-in-only asynchronous adaptation; `ab6bce05` adds page-aligned pin-by-need and a PCIe-share floor. `docs/DETAILS.md:202-224` explains arena async completion, `STRATA_PIN_BY_NEED`, and Windows pinned-memory headroom (`STRATA_PIN_RESERVE_MIB`). Keep these native safeguards when adding pressure admission.

**Linux file tier has materially changed.** `c85cc6dd`, `8b1139d0`, `82c80ac4`, then `ecf2bdcb` introduce/enable page-cache zero-copy, whole-blob preads and predicted read-ahead, with a decode gate based on both cache room and useful bytes. `FileExpertSource::set_io_prefetch`, `warm_scored`, `zc_roles`, `gate_tick`, `gate_capacity` are exposed in `expert_source.hpp:918-1034`; startup selection is `generate.cpp:5757-5788`. Defaults are `STRATA_COLD_OVERLAP=4`, `STRATA_IO_PREFETCH=1` for eligible Linux sources and an adaptive room/usefulness gate. GGUF and `experts.bin` eligibility differs. The log explicitly says this I/O-prefetch path is unavailable elsewhere; **these default gains cannot be attributed to Windows**. `docs/DETAILS.md:272-310` records upstream measurements and limitations.

## PLE and KV

`PleIoOptions` (`include/strata/kernels/ngram.hpp:150`) exposes `max_inflight`, bounded `cache_rows`, `io_thread`, and full-table `lock`. `PleTable::issue/collect`, `prefetch_rows`, `gather_batch`, `locked`, `io_report` are existing reuse points. RAM mode maps the actual GGUF table and attempts `mlock` on POSIX or working-set reservation plus `VirtualLock` on Windows; `locked()==false` means pre-touch alone, not guaranteed residency. No native locked partial-table budget is exposed by this options struct; the direct row cache is the existing bounded warm tier.

Changes since base include `62497bff` (mapped prefill gathers prefetch a window ahead), `a2de7446` (reader-state lock for shared table access), and `36381540` (batch reuse for reordered/duplicated prefetched keys). Crucially `0cf3d510` changes the slow-direct probe to **warn without switching on every platform**; `STRATA_PLE_AUTO_MMAP=1` restores old 0.1.42 automatic switching (`generate.cpp:4067-4087`). Freeze the actual PLE mode in old/new A/B; absence of a CLI flag is not identical behavior across versions. `b25b3097` makes Linux setup select whole-table RAM on SSD too when RAM allows; this is setup policy, not proof Windows successfully locks this host's table.

KV already has VRAM resident cells backed by host pools: `KvStreamMap`, `KvHostPools`, `kv_stream_resolve` (`include/strata/kernels/kv_stream.hpp`, `src/kernels/cuda/kv_stream.cu:214`). `c41c0ebb` changes WSL host pinning to ordinary memory plus `cudaHostRegister` (`STRATA_KV_HOST_REGISTER`), and `3980a5ce` adds HIP VMM for elastic KV. Neither establishes SSD as an active attention tier. `f0010a60` now auto-sizes conversation RAM cache after load when no explicit `--conversation-cache-mib` is present: 40% above the parking floor, capped at 8192 MiB, off under 1024 MiB (`docs/DETAILS.md`, commit description). `d9cb22d2` adds a minimum park gain; `53f72571` reduces reserve retained by reparked buffers. Pin explicit cache size for comparability and budget conversation RAM alongside weights.

## CPU topology, I/O and startup

`include/strata/kernels/cpu/pool_plan.hpp::plan_pool_workers` now incorporates physical cores per package, quota, reserved host/auxiliary capacity, a measured cap of 32, and on hybrid CPUs with more E than P cores, P cores minus host plus half the E cores. Relevant changes: `5ece068f`, `036c8f6e`, `bec4c838`; `88b29d48` classifies Linux LP-E PMU CPUs as efficiency cores. `1ab0fbd0` adds opt-in `--pool-affinity measure`; `051b9703` adds `--host-core sibling`.

`7a559958` and `e2b44649` add pool logical-CPU reporting/`--pool-cores`, reading real SMT pairing on Windows/Linux; `8c41d361` carries Windows thread naming in `pool.cpp`. Source and pure planning are in `pool_plan.hpp`; wiring is `serve/server.py::pool_cores_args` (`:3157`) and `ExpertPool` construction. Use these before maintaining another affinity-list parser. `--aux-cpus` is **Linux-only**, including native helper thread pinning and a `/proc/self/task` sweep; per-request `strata_tune.aux_cpus` exists (`docs/DETAILS.md:2147-2173`). This does not solve Windows role placement. NUMA pool (`4bd59126`, `e4d22e7e`) tries splitting on multi-node hosts by default; `pool.cpp:751-755` and `numa_pool.hpp::pick_numa_pool` keep a one-node machine unchanged. Do not infer value on this host without inventory.

`src/platform/direct_file.cpp` already has queued worker I/O: Windows overlapped submits (default 4 issuing threads), Linux blocking direct preads on workers (default 16); `STRATA_IO_THREADS` controls the pool. Native OS hints are `platform::advise_willneed`, `FileExpertSource::prefetch_pairs/warm` and PLE batch page prefetch. Linux file-tier upgrades above are per-source read scheduling, not a 1/2/3 physical-disk placement planner.

An especially relevant new measurement reuse point is **`484e06b9612af17380aa11c4bf6163127acc7b7c`**: `src/core/expert_source.cpp:750-922` times random 1 MiB pieces with 8 direct-read workers against 3 mapping first-touch workers; `platform::file_tier_prefers_direct` (`memory.hpp`) requires cache-held fraction <0.5, direct >=4 GB/s and direct/cache >=1.3 (<30% held) or >=1.5. `STRATA_FILE_TIER_PROBE=0` disables the override. It is Linux-only and a local read-path choice; its commit explicitly says fast-drive default change was proposed without validation on such a drive by the author. Reuse measured costs/provenance, and still perform this project's physical-disk contention and multi-disk experiments.

## Calibration and auxiliary backend seams

Native `tools/calibrate.py::measure` already sweeps PCIe share, draft confidence, worker counts, adaptive-tier parameters, split prefill pipe, and AMD shared stream (`eb6e0f1e`, `125025a7`). `SWEEP_ROUNDS=3`, `MIN_GAIN=0.03`, `sweep` reverses alternate rounds; `warm_up` defaults to two rounds. This is not the project's exact warm1/repeat3 workload or a full quality/physicaldisk evaluation. `restart` retains earlier results if a later candidate cannot start. New control paths (`strata_control/autotune.py`, `tune_session.py`, `tune_machine.py`, `tune_engine.py`) and `strata_cli/launch/runner.py::tune` (`:1326`) persist/reuse results; `176e11a5` adds reuse for same model/choices/computer, and `--retune` forces new measurements. `2a22daa4` fixes shipping calibrate in the bundle.

Native runtime cost adaptation also deserves reuse: `PcieAuto` (`generate.cpp:2181`) starts from probed link bandwidth then refines against CPU expert speed; `ab97f174` extends canonical packs, `b0e88eb1` ports refinement to HIP. `04be241a` adds opt-in per-layer measured `PcieModel`/`STRATA_PCIE_BALANCE` (`expert_source.hpp:392`; `generate.cpp:3601`). These model CPU/GPU expert sharing, not Arc/NPU/cold-storage costs.

Standalone Arc is substantially supported, but **mixed CUDA+Arc execution is not native**. `CMakeLists.txt:12-21` makes SYCL a separate, mutually exclusive backend and returns into `sycl/`; `docs/INTEL.md:165` explicitly says the engine has no backend seam to slot it into. `23b3dfc2`/`8be3f916` add a Linux SYCL engine package and `424b364a` keeps `--version` GPU-free. `docs/MULTI_GPU.md:113` excludes Intel/mixed-vendor multi-GPU. `RemoteExperts` (`include/strata/core/remote_experts.hpp:18`) is a tier on **another CUDA device**, with `preflight/open/begin/finish` and pinned host row return; this is a useful contract to generalize, not proof it accepts Arc.

Vision is already a separate process behind `serve/server.py::Vision` (`:2602`, `reader_args`, `_start_reader`, `_readline`) with READY/encode timeouts. `strata_control/vision_reader.py` chooses readers; `cac4816a` adds SYCL GPU reader choice, CPU reader remains available. An exact-word source search of the relevant engine/serve/vision/control/build paths found no `NPU` or `OpenVINO` implementation. The existing vision process protocol is the best candidate seam for an NPU reader; host support, embedding identity, fallback and end-to-end gain remain unvalidated.

## Frozen harness compatibility and next integration boundary

Do not replace the active frozen bridge in place. Source diff from base is large even in relevant files: `serve/server.py` +2669/-281, `generate.cpp` +4276/-358, `expert_source.cpp` +1600/-92. New upstream server imports `strata_control` modules at startup, handles component-resolved engines (`9ddebc1b`), config/user-argument precedence, drafter selection and GPU roles. A standalone copied old `serve/` directory is not a closed current bridge dependency set.

Specific behavioral drift to freeze or review:

- `serve/server.py::engine_args` (`:3076`) merges `user_args`, applies `drafting` selection and `mtp:false`, inserts vision/reserve, split/parallel/pool flags, then learned-profile handling. Record final resolved argv/env and profile state, not JSON alone. Config `args` splitting also changed in `8101a890`.
- `model_card_sampling` now supplies defaults when omitted (`server.py:5084`, `:8056`): original Qwen thinking temperature 1.0, non-thinking 0.7 and respective top-p/top-k/penalties. Freeze explicit sampling, seed, reasoning behavior and shared settings for deterministic quality arms.
- `f31b6efd` makes `fit_max_tokens` on by default; `server.py:4890-4908` can shorten output budget. Make the intended cap/context/strictness explicit rather than silently accept a different effective request.
- Protocol remains actual integer tokens from `StrataEngine.generate` (`server.py:2186`) and READY/T/DONE, plus batch BT/BDONE; current batching/slot/control/nonfinite handling is broader. Preserve error/nonfinite semantics and completion accounting while porting diagnostics.
- **Actual token-ID capture is a local extension, absent in fetched upstream.** Current local `serve/server.py:2784`, `:4046`, `:4256`, `:5297`, `:6230` gate `hetero_capture_token_ids` and publish `strata_diagnostics.actual_generated_token_ids`. `tools/hetero_compare_quality.py:406`, `:513` requires those actual emitted IDs. Re-encoding visible text cannot replace this evidence. Port the opt-in instrumentation to every current bridge generation path used by the frozen suite; source-review its position before detokenization/filtering, then validate offline before a model run.

Recommended boundary: finish active source293b diagnosis independently; then prepare a separately pinned current-upstream engine/bridge arm with the smallest reviewed instrumentation port and explicit resolved configuration. First establish current upstream quality/runtime acceptance and warm1/repeat3 evidence; only then port measured Hetero extensions onto its native memory/I/O/CPU contracts. No source capability or upstream benchmark in this audit completes GTi15 host acceptance or the requested historical/current model A/B.
