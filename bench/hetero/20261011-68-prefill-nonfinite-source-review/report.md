# Prefill non-finite diagnostic source review

This is a read-only source inventory, not a diagnosis of the Run66 output. The pinned upstream v0.1.42 tree (`61b3fb5d`) is an ancestor of the pinned Hetero v0.1.42 tree (`8cf0e89b`). In the prompt-engine files checked here, `src/prefill/prefill.cpp` and `src/prefill/gemm.cu` have identical Git blobs in both trees. Hetero v0.1.42 adds a zero-logits report in `src/core/verify.cpp` and separate PLE-RAM/affinity reporting in `src/program/generate.cpp`; those additions do not put a probe between prefill activations.

The source-pinned diagnostic behavior and the bounded probe opportunity are:

1. **The prefill core is shared by both v0.1.42 binaries.** At upstream `61b3fb5d` and Hetero `8cf0e89b`, `src/prefill/prefill.cpp` is blob `e36bb6884ad4e50f34ca12cb6141f63f704ace03`, and `src/prefill/gemm.cu` is blob `88ecb7933c5061ef7ae6bf2abb908a2c7703d200`. The Hetero-only `verify.cpp` addition is blob `46a64aecfaf569ee1b0fc60a0f38488e13dd636d`; its upstream counterpart is `3e9ec069a5f706df76ab43ee87144ec3317d3362`. This makes the prompt arithmetic a common source path, while the verifier diagnostic is branch-specific.

2. **A chunk processes PLE, attention, then feed-forward work by layer.** In `Prefill::run_impl`, PLE rows are gathered ahead on a host thread and landed at layer 1 (`prefill.cpp:2059-2081, 2152-2187, 2431-2433`). The layer-1 PLE block runs before its two hyper-connection halves (`2434-2486`). Half 0 selects GDN or QSA (`2487, 2557-2581, 2582-2810`); half 1 runs the MoE path, combines into `m.bo`, and each half writes back to residual `m.R` (`3852, 3908-3939`). `run_impl` itself has no `cudaDeviceSynchronize` call; it uses stream/event ordering and explicit stream waits at boundaries.

3. **The main scratch region is intentionally reused.** `prefill.cpp:905-908` states that attention and MoE share the same region because their halves run sequentially. PLE batch post-ops also carve the region at layer 1 (`2440-2457`), before the attention/MoE halves. Any diagnostic that reads temporary buffers must be queued after their producer and before the next user overwrites them. The surviving residual `m.R` and the completed outputs `m.bo` are less ambiguous probe targets than shared scratch.

4. **`STRATA_DBG_NAN` checks the MoE result after the MoE, then selected prompt-end state.** The layer check follows `moe_combine` (`prefill.cpp:3852-3882`): it stream-synchronizes `m.cs`, copies GU/H/Dm/bo to host, counts non-finite elements, and prints the first bad layer for that chunk. It does not scan GDN or QSA outputs before the MoE, nor the PLE output/history at its producer. At prompt end it checks only the last residual row, PLE history, and the first 65,536 GDN-state floats (`4028-4040`). This is useful coverage but cannot identify the first bad activation earlier in the layer.

5. **The GEMM diagnostic is a different, HIP-only probe.** `gemm.cu:51-67, 798-812` guards `Gemm::f16_inplace` with `__HIPCC__`; it counts non-finite widened FP16 outputs and calls `hipStreamSynchronize` for each such GEMM. It is not the CUDA v0.1.42 Run66 path. The ordinary `Prefill::run_impl` uses stream/event waits; `STRATA_PF_STEP_SYNC=1` adds compute- and copy-stream synchronization after named layer steps (`prefill.cpp:2412-2425`). That slow mode reports stalls, not activation finiteness.

6. **The existing post-head diagnostics are late and path-specific.** The ordinary token loop checks logits for non-finite values when `read_logits` is enabled (`generate.cpp:12310-12346`); finite all-zero logits do not trip that check. Hetero v0.1.42's `STRATA_DIAG_ZERO_LOGITS=1` is in `Verifier::run` (`verify.cpp:2174-2234`): after sample IDs are read and the compute stream is synchronized, it copies logits only when an output ID is zero, then reports finite/NaN/Inf/zero counts, finite argmax, and selected values. It does not inspect prefill activations, and the upstream v0.1.42 source has no matching addition at that location. `STRATA_DBG_NAN` in the verifier also scans the head, but only after the verifier has produced output (`verify.cpp:2174-2190`).

7. **Prompt borrowing and state reset are separate lifecycle steps.** The generator plans and synchronizes an expert-cache loan before `prefill.init`/`prefill.run`, then refills borrowed cache slots after prefill (`generate.cpp:12131-12206`; the service path has its own lend/refill block around `6574-6600, 8017, 10461-10484`). `session_zero` clears residual, owned GDN state, QSA state, PLE history, and PLE token predecessors (`session.cpp:140-162`); the serve loop calls it when starting a zeroed request (`generate.cpp:10209-10232`). MTP prompt KV is filled from each prefill chunk's residual/next-token pair (`generate.cpp:12175-12184`); its tail window and optional per-group synchronization are controlled in `mtp.cpp:1154-1248` by `STRATA_MTP_PREFILL_SYNC`. These are candidate lifecycle boundaries to preserve in a future trace, not evidence that state reuse caused the observed output.

8. **Run18 is a limited historical comparison.** Its `long1k-review.json` reports a v0.1.40.4 long_1k pass with H4 token IDs/text equal, `STRATA_DIAG_ZERO_LOGITS=1`, and zero diagnostic rows; its review says the finite/NaN/argmax values were unavailable. The prepared contract records `STRATA_DBG_NAN` absent and `--ple-io ram` with a 12 GiB PLE reserve. It therefore shows that the short/long task passed under a different build/control set, but it does not show what the v0.1.42 prompt intermediates contain or that a fix occurred.

9. **A narrow first-non-finite probe can stay on the existing compute stream.** One instrumentation candidate is a default-off, explicitly enabled finite-scan kernel on `m.cs` immediately after PLE writes `m.R`, after GDN/QSA has produced its `m.bo`/residual, and after MoE combine/writeback. Each scan would atomically preserve only the first `{chunk, layer, half, stage, index}` in a device flag. Read the flag once at an existing chunk boundary where `m.cs` is already synchronized (for example, before the existing `on_chunk` handoff), rather than adding `cudaDeviceSynchronize` or a blocking host copy after every GEMM. This could narrow which instrumented producer first has a non-finite output without reading temporary scratch after its lifetime ends. Even without a global sync, scan kernels, atomics, and the final flag read add work and can perturb or mask a race; they are not a no-effect probe. It has not been built or measured and is only a hypothesis, not a math fix or an established cause.

Run-context evidence is kept separate from the source findings: root reports Run63's Hetero v0.1.41 head as all-NaN, and Run66's upstream v0.1.42 SSE shows the first failing long_1k warmup/formals with 128 generated IDs all equal to 0 and a 128-byte bang-loop. The quality gate stopped at long_1k; this review does not infer which source stage caused either signature. No code was changed, and no compile, test, device, model, API, or retry action was performed.
